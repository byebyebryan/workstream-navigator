## Scope and privacy boundary

D17.1 corrects retained-state paging, active schema identity, private process
cleanup, tmux metadata parsing, and CI reproducibility. It does not add a page,
provider abstraction, compatibility path, or transcript surface.

Automated tests and live acceptance use disposable state roots, repositories,
provider homes, and private tmux sockets. Existing Codex authentication was
copied at mode `0600` only into the disposable Codex home and was never printed,
hashed, parsed, or committed. No provider prompt or turn was submitted, and no
user Runtime or provider state was inspected or changed. Evidence retained here
contains only versions, aggregate test counts, behavior assertions, and
executable checksums; it contains no terminal capture, provider payload,
credential, native identifier, prompt, response, or transcript.

## Correctness result

All retained Workstream, unresolved-operation, onboarding-operation,
Runtime-inventory, and provisional-marker pages expose at most 128 rows; each
bounded SQLite query may read one additional sentinel row to signal
continuation. Complete process-local views hold ordered base scans under stable
read snapshots before current binding and lifecycle hydration. Exact request
lookup does not scan unrelated retained history, and terminal operation rows
are not deleted or excluded to satisfy a page limit.

The active schema identity is explicitly version 14. Linux private process
cleanup reaps its direct child and waits a bounded interval for the process
group; an exact zombie is treated as dead only after the usual identity and
group checks, while live or ambiguous evidence still fails closed. tmux
multi-field control queries use printable `|` separators because tmux 3.4
normalizes literal control separators in format strings. Delimiter collisions
in legacy free-form evidence fail closed, and provider-pane contents are never
queried or captured.

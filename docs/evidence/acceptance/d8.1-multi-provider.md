## Falsified invariant and approved correction

The mixed run changed the model through Codex's native `/model` UI while the
managed TUI had selected the `wsnav-observer` profile. Codex prepended
`model` and `model_reasoning_effort` settings to that profile, before the
WSNav-managed declaration marker.

This contradicts the V1 contract that the owned profile contains only the hook
feature and four observation hooks, never selects or changes model settings,
and remains a byte-exact managed prefix plus only the narrow native
hook/project-trust suffix. The exact removal path correctly classified the
file as modified and refused to delete it. After every Runtime and helper was
stopped, the complete disposable Codex home was removed, so no acceptance
artifact survived.

The approved correction treats the file as an optional bounded provider-owned
model prefix, the byte-exact WSNav declaration, and the existing validated
native hook/project-trust suffix. Only non-empty string `model` and
`model_reasoning_effort` values are accepted in the prefix; their bytes are
preserved opaquely and never enter WSNav state. Unknown, malformed, duplicate,
misplaced, or oversized settings continue to fail closed.

Observer updates preserve that prefix exactly. Observer removal deletes the
managed declaration and native trust, but leaves a model-only profile rather
than erasing the native choice; a later setup treats that unowned residue as
foreign.

A second disposable run used real Codex CLI `0.146.0`, an isolated Codex home

repository, and an isolated WSNav state root. The native profile-selected TUI

and mode `0600`, while the managed marker, hook declaration, hook trust, and
project trust were all absent. A subsequent setup refused to adopt that
unowned model-only profile. No disposable process remained and the complete
Codex, repository, and state root was removed.
